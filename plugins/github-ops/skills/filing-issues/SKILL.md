# filing-issues

課題を GitHub issue にするとき、起票先のリポジトリを決める。

起票先は、その課題を直すために編集するファイルを git 管理しているリポジトリにする。
どこで症状が出たかでは決めない。

## 役割ごとのリポジトリ名を引く

起票先は役割で決まる。役割ごとのリポジトリ名は、
利用者のグローバル CLAUDE.md (`~/.claude/CLAUDE.md`) に書いたものを使う。

| 役割 | 中身 |
| ---- | ---- |
| ハーネス設定のリポジトリ | `~/.claude/` へ配る CLAUDE.md・skill・hook・`settings.json` を git 管理するもの (dotfiles など) |
| 横断のリポジトリ | 複数のリポジトリをまたぐ作業の issue を置くもの |

CLAUDE.md に書く形の例は次のとおり。

```markdown
## issue の起票先

- ハーネス設定: `<owner>/<repo>`
- 横断の作業: `<owner>/<repo>`
```

書いていない役割に当たる課題が出たら、起票の前に利用者へリポジトリ名を聞き、CLAUDE.md に書くかを確かめる。

## 課題の対象ごとの起票先

| 課題の対象 | 起票先 |
| ---- | ---- |
| `~/.claude/skills/` に載るグローバル skill、hook、`settings.json` の permission / sandbox / env | ハーネス設定のリポジトリ |
| グローバル CLAUDE.md、plugin の有効・無効構成、MCP server 設定 | ハーネス設定のリポジトリ |
| `/doctor` などハーネス診断から出た課題 | ハーネス設定のリポジトリ |
| そのリポジトリのコンテンツ・CI・ビルド | 作業リポジトリ |
| plugin や別リポジトリで管理する skill 群 | その skill のリポジトリ |
| プロジェクトローカル skill (`.claude/skills/`)、プロジェクトの `.claude/CLAUDE.md` | 作業リポジトリ |
| 複数のリポジトリをまたぐ対応 (同じ変更の横展開、横断の棚卸し) | 横断のリポジトリに 1 本 |

## 紛らわしいところ

- `~/.claude/skills/` に並んでいても、実体が別リポジトリにある skill (symlink の先、plugin の install 先) はそのリポジトリの管轄。
  ハーネス設定のリポジトリに実体があるものだけが、ハーネス設定のリポジトリの管轄になる。
- ハーネスの挙動に見えても、原因がプロジェクトの `.claude/settings.json` や
  `.claude/CLAUDE.md` にあるなら作業リポジトリ。

## ハーネス設定と作業リポジトリにまたがるとき

1 つの課題を直すのに、ハーネス設定のリポジトリと作業リポジトリの両方を編集するときの決まり。
同じ変更を多くのリポジトリへ入れるときは、次の節に従う。

主管轄側に 1 本立て、他方に残る作業は節として本文に書く。
それぞれ独立して進む作業なら、両方に立てて相互リンクする。

## 複数のリポジトリをまたぐとき

同じ変更を各リポジトリへ入れる横展開・横断の棚卸し・順番のある移行は、横断のリポジトリに issue を 1 本立てる。
対象リポジトリごとに立てると、全体の進みを見る場所が無くなり、共通の背景が issue の数だけ写される。

本文に置くものは次のとおり。

- 直し方の実体への参照 (skill、先例の PR)。手順そのものは写さない
- 対象リポジトリのチェックリスト。1 リポジトリ 1 行で、進めるたびに埋める
- 対象を判別するコマンドと、一覧を取った日付。対象が増減したときに取り直せる

各リポジトリには issue を立てない。各リポジトリの PR から横断の issue を参照し、
チェックリストの行に PR をリンクする。

## 管轄違いに後から気づいたとき

1. `gh issue create -R <起票先の owner/repo>` で起票し、本文冒頭に起票元 issue へのリンクを置く
2. 元 issue に転記先をコメントで残す
3. 元 issue をクローズする
