# ネクサス課題ワークショップ

出典: 『組織の壁を越える』(英治出版, 2018)。
この skill の Step 1〜4 の問い・基準・例は、同書の序章にあるアクティビティ「あなたのネクサス課題」による。

## Overview

『組織の壁を越える』序章のアクティビティ「あなたのネクサス課題」を進行し、
成果物を HTML レポートで出す。

**ネクサス課題** = いま直面している最も差し迫った課題のうち、自分のチーム・部門・地域の
なかだけでリーダーシップを発揮しても解決できず、境界を越えたリーダーシップでしか
解決できないもの。1つだけ選ぶ。

書誌情報と背景知識 (5つの境界、6つの実践、ネクサス効果、グレート・ディバイド、目次) は
`references/book-context.md` にある。ワークの意図を説明するとき、Step 4 で境界を特定
するとき、Step 5 で読む章を選ぶときに読む。

## When to use

- 「越境」「サイロ」「部門横断」「組織の壁」の課題を、着手できる単位に絞りたい
- 課題は挙がっているが、どれに本腰を入れるか決まっていない
- 本書を読む前に、自分の課題を持って読み始めたい

**使わない場面**: 目標設定・OKR 策定一般、単一チーム内で完結する課題の整理、
すでに解くべき課題が確定していて実行計画だけが要るとき。

## 進行の原則

- **1ステップずつ進める。** そのステップの問いだけを投げ、ユーザーの回答を待つ。
  先回りして次の質問をまとめて出さない。
- **課題はユーザーの言葉で書く。** Claude が候補を代筆して埋めない。言い換えの提案は
  「こういう言い方もできる」と示して選んでもらう。
- **空欄は空欄のままレポートに出す。** 埋まっていない象限を推測で補完しない。
- 所要 30〜45分。個人ワークでもチームワークでも同じ手順で進む。
  チームの場合は各自ステップ3まで書いてから見出しを突き合わせる。

## Step 1: 課題を3〜5つ書き出す

いま直面している、境界を越えたリーダーシップの課題を3〜5つ挙げてもらう。

問い: **あなたや組織を成功に導くために、本当に重要なものは何か?**

細かいレベルではなく、大きく考えるよう促す。書籍は粒度の例として次のものを挙げる。

- 組織の重要な問題を解決する
- 新しい革新的なプロセス、製品またはソリューションを開発する
- 重要な組織変革を主導する

粒度が細かすぎる回答 (「週次の定例を改善する」等) が出たら、その課題が何のために
あるのかを1段上げて聞き直す。

## Step 2: 境界を越えないと解けないものを1〜2つ選ぶ

Step 1 で書き出した課題のうち、**自分のチームや部門、地域のなかだけでリーダーシップを
発揮しても解決できない**ものはどれか。以下の3基準を最もよく満たすものを1つか2つ選ぶ。

| 基準 | 満たすとはどういうことか |
| ---- | ---- |
| 境界を越える必要がある | さまざまな集団のなかに大きな方向性・団結力・責任感を築かないと前に進まない |
| 深い変革を必要とする | システムや構造だけでなく、人間関係やアイデンティティ (「何をするか」だけでなく「われわれは誰か」) の変革が要る |
| 新しいアプローチを必要とする | 過去に機能したやり方がもう十分に役立たない。新しい技能・戦術・ツールが要る |

どの課題も基準を満たさないときは、選ばずに Step 1 へ戻る。基準を緩めて無理に選ぶと、
後段の4象限が埋まらない。

## Step 3: 見出しをつける

残った候補から、バウンダリー・スパニング・リーダーシップのアイデアを応用するのに
一番ふさわしい課題を1つ決める。**これがネクサス課題**。次の形式で見出しをつける。

- 短めの見出しで表現する
- **「いかに〜するか」の形式**にする
- **行動を示す動詞を必ず入れる**

書籍の例: 「部門の垣根を越えたコラボレーションを促し、もっと顧客中心の製品や
ソリューションを開発・提供する」が課題なら、見出しは「いかにサイロを壊すか」
「いかに部門横断的なコラボレーションを促して顧客ニーズに応えるか」。

見出しは円の中心に入る。20〜40字に収まらないなら、まだ課題が絞れていない。

## Step 4: 4つの問いに答える

見出しを4つの問いに即して展開する。1問ずつ順に聞く。

| 問い | 聞くこと |
| ---- | ---- |
| **何?** | 課題は何か? それを表現する |
| **なぜ?** | なぜこれが課題なのか? **関係する境界や集団をリストアップする** |
| **どのように?** | この課題にどのように対応しようとしてきたか? 何が有効で、何が有効でないか? |
| **もし〜なら?** | もしこの課題を解決できたとしたら? どんな新しい可能性が生まれるか? |

「なぜ?」では境界の種類 (垂直/水平/ステークホルダー/人口属性/地理) を提示して、
どれに当たるかを本人に選んでもらう。定義は `references/book-context.md` にある。

## Step 5: レポートを出力して読書につなげる

`assets/nexus-report-template.html` をコピーし、`<script id="nexus-data">` の JSON
だけを書き換える。HTML と CSS と描画コードには触らない。

```sh
mkdir -p ./tmp
cp ${CLAUDE_SKILL_DIR}/assets/nexus-report-template.html \
   ./tmp/nexus-challenge.html
```

JSON のキーと期待する値はテンプレート内のコメントに書いてある。書き換えたら
`./tmp/nexus-challenge.html` をユーザーに見せる。

レポートには6つの実践 (第4〜9章) の一覧が入る。ネクサス課題に効きそうな実践を選んで
`priority` を付け、どの章から読むかの当たりをつけて渡す。ここまでがワークの完了。

## Common Mistakes

| やりがち | どうなるか |
| ---- | ---- |
| Step 1 で1つしか挙げずに進む | 比較対象が無く、Step 2 の選定が「消去法」でなく「追認」になる |
| 見出しに動詞が無い (「部門間連携」) | 行動が想像できず、Step 4 の「どのように?」が書けない |
| 「なぜ?」で境界を挙げずに背景説明で埋める | 誰と越境するのかが決まらず、6つの実践に接続できない |
| Claude が象限を代筆する | 本人の課題認識ではなくなり、読書の動機づけという本来の目的を失う |
